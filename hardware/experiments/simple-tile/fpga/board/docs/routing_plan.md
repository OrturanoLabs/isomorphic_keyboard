## What has to be routed (r6 census: 45 nets, 0 tracks, 99 unconnected)

- **5 forward outputs, edge-critical**: T_clk, L_clk, L_latch, B_data, B_W
  from U1 pins 35/19/31/30/27 through series positions R7-R11 (0R,
  0402, already placed in the QFN escape corridor) to their JP pads.
  T_clk/L_clk are true TBUF (park-at-Z); L_latch and B_data are 2-branch
  chassis merges -- the tree segments on THIS tile are single-ended
  point-to-point to the contact. Return path continuity for these five
  is the layer-comparison's decisive electrical criterion
  (docs/termination.md: unterminated far end, bench gate B2).
- **9 channel inputs + 12 key matrix inputs**: short radial runs to the
  socket pads (SW at lattice P=18.3597 / R=15.9 on the F side).
  Key nets carry internal pull-DOWNs (cst PULL_MODE=DOWN), bench fallback
  external 10k -- nothing to provision in copper besides reachability.
- **Power**: VCC pins 1/25/36 + JP_VCC entry, VCC1V2 pins 12/37 behind
  FB1 (bead at the load side, 4.6 mm from U1.12), VCC1V2_RAW a ~31 mm
  run from the LDO cluster (top-left) to the bead -- route wide, IR drop
  documented as ~1.5 mV at est. 30 mA (docs/power_reg.md); GND pins
  2/26 + EPAD 49. EPAD = only GND pad on the body underside: the exposed
  pad needs solder/paste + a via plan (thermal-via decision still open,
  docs/readiness.md) -- 2L vs 4L changes this answer.
- **Config/bench**: JTAG 4 + JTAGSEL + MODE0/1 + READY/DONE/RECONFIG_N,
  each already on a TP (checker N4; TP_GND exists). Keep all 11 TPs
  reachable post-routing: TP_VCC/TP_VCC1V2 for B1 rail-scoping,
  TP_TCK/TMS/TDI/TDO for programming, TP_DONE/READY/RECFG for B3 boot.

   **Machine-checked assignment table now exists**: `docs/netclasses.json`
   generated by `tools/netclass_prep.py` (2026-10-15, self-checks N1-N5:
   exact 45-net partition 6/4/9/12/4/10, series topology re-read off the
   pcb, power set, JP/presence coverage, vacuity control) -- convert it
   into KiCad net classes rather than re-typing net lists by hand.
2. Fanout phase first (recorded freerouting trap: no SMD-to-plane

   Xmx1500m per the downstream-prep note and docs/LEDGER.md; kill

3. Attempt A (2L): B-side GND-pour-centric, edge-critical outputs with
   adjacent GND pour/trace return; power by fat traces/pours; sockets
   F-side kept solderable.
4. Attempt B (4L) if A leaves opens/violations or return discontinuities:
   SIG/GND-SIG/GND or SIG-GND/VCC-SIG stack; record the choice.
5. Criteria table (fill at decision time, no pre-judged winner):
   unrouted opens (acceptance: 0) - kicad-cli DRC violations at the SAME
   rule file (acceptance: 0) - via count - worst return-path discontinuity
   on the 5 edge-critical nets (mm off-plane) - routed length census of

   pad/TBUF/hop values are ALL unknown today) - assembly risk
   (via-in-pad? via plugging cost) - finished-cost delta: capture at
   quote time (no prices asserted in advance).
6. Rechecks before calling it: schematic parity (S4) re-run, 6-neighbour
   TileTiling clearance re-run (GK), updated length/loading record into
   the FPGA-02 checkpoint, readiness.md ledger updated.

## Channel-capacity measurements (r6, machine-derived)

`tools/routing_geo.py` (FPGA-02 prep, batch 3/4) measures obstacle boxes
from PADS + HOLES (NPTH drill +0.15 mm annulus), NOT courtyards --
docs/LEDGER.md trap quantified for this board: socket hotswap pads stick
~2 mm out of the courtyard, so a courtyard-only model would estimate
7.56 mm where the true obstacle gap is 2.88 mm. Metric = exact
rect-to-rect euclidean min over all pad/hole AABB pairs (rot==0
asserted; conservative by the square-annulus approximation). Full data:
`docs/routing_geo.json`; reruns are deterministic from the r6 pcb
(sha256[:12] c7d5b66fa1db).

- Socket corridors: 23 lattice-adjacent pairs. In-row (pitch 18.36 mm)
  corridors are the bottleneck: obstacle gap 2.883 mm = hotswap pad
  corner to hotswap pad corner (SW1 K1 pad (+5.84,-5.08) vs SW2
  edge-trimmed VCC pad (-7.08,-2.54); y-offset 0.04 mm, effectively
  end-to-end). Capacity = 6 tracks at 0.2/0.2. Best-case diagonal
  corridors reach 9.02 mm (22 tracks).
- U1 escape pinch points (obstacle gap): SW6 3.05 mm NPTH tooling hole
  (rel +2.54,-5.08 -> world (11.72,10.82)) vs the U1 north pad-toe row
  = 0.375 mm -- nothing passes on the x~10.0 line toward the top band;
  north escapes must jog around that hole. Bypass caps C1-C6, FB1, R2
  sit at 0.52-0.6 mm (0-1 track) by design (proximity decoupling);
  R7-R11 series parts are deliberately in the south corridor.
- JP band: min pad-box to outline BBOX edge = 1.3 mm (info only; the
  true stepped-edge distance is a GK recheck matter, not measured here).
- HW4 tool confirmation in-tree: pcbnew-API via KiCad 10.0.6 flatpak
  works on this pcb (see next section); geometry parsing needs no KiCad.

## QFN EP (pad 49) thermal-via decision analysis

Facts: EPAD 2.7x2.7 mm on net GND (netlist: GND = U1 pins 2/26/49);
package requires EP grounded. Board power from power_reg.md (batch 1):
the FPGA consumes ~50-60 mW in total (1.2 V core <= ~30 mA est plus
small 3.3 V IO); the LDO, not the FPGA, carries the 2.1 V drop heat.
At 50-60 mW even a pessimistic via-less QFN RthetaJA gives <= ~6 K
rise -- thermally irrelevant on this board.

Decision analysis (decision stays with the FPGA-02 layout task):
1. Thermal vias NOT required for cooling (power class too low by
   ~2 orders of magnitude).
2. EP MUST be soldered (GND net connection); SMD pad + multi-window
   paste stencil (e.g. 4-window ~50-60% coverage) to avoid float/voids.
3. Via-in-EP array: SKIP -- adds via-in-pad filling/plugging fab cost
   and solder-wicking void risk with zero thermal need; keep the
   JLC capability question in docs/quote/README instead.
4. GND-return/stitching is the only open sub-item (2L case): EP pad on
   B.Cu otherwise ties downward only via pins 2/26. IO return currents
   at 1 MHz class make this benign; if the 2L fanout leaves a poor
   pour connection, add up to one ring of 0.6/0.3 GND vias OUTSIDE the
   EP outline -- the measured EP-outline-to-pad-row corridor is
   1.175 mm, which fits one via ring (0.6 pad + 2x0.2 clearance = 1.0).
   Final call in the FPGA-02 fanout phase; no geometry change now.

A. Classed router input FIRST (batch-5 empirical chain, docs/
   routing_plan.md "Router I/O path" section): run tools/export_dsn.py
   on the pcb, then tools/dsn_class_split.py -> tile_gw1nz_classes.dsn

   (batch 6). On r6: 58 power pads, 6 anchors (QFN EP + JP contact
   pads), 52 pads planned with a CLEAN fanout choice each (0 conflicts,
   0 cross-net collisions at 0.2/0.2; surface escapes are enough
   everywhere on 2L, so the default plan is via-free), and 46/52 pads
   additionally have a feasible direct-via candidate. The 6 that CANNOT
   take a direct via (the 4L via-attach blockers -- the LEDGER
   SMD-to-plane trap would need work-arounds there, e.g. longer
   dog-bones) are: U1-2, U1-26 (GND), U1-37 (VCC1V2), C4-2, C5-2
   (VCC1V2), C8-2 (GND). Then: (1) power fanout stubs for every SMD power pad group
   first (VCC/VCC1V2/GND; LEDGER trap: freerouting cannot attach SMD
   pads to planes -- on 4L this means stub+via before routing; on 2L
   keep the same deterministic stub step for testability);
   (2) config straps MODE0/MODE1/JTAG* short stubs to JP;
   (3) U1 escape: radial exits per the ring corridor, north exits jog
   around the SW6 tooling-hole pinch (x~10.0, gap 0.375 mm);
   (4) R7-R11 level-shifter stubs (south corridor by design);
   (5) K1..K12 and channel-net escapes along measured in-row corridors
   (6 tracks min) and diagonal corridors (up to 22);
   (6) contact-band fan-in to the 19 JP pads (keep pads probe-able).
   4L alternative adds In1=GND/In2=VCC planes per the discrete recipe.
C. Closure: DRC both variants path unchanged (0 errors target, warning
   corpus = known silk/overlap set), net parity S4 re-run, tile-tiling
   GK re-run, length/loading report for the FPGA-02 checkpoint, DSN
